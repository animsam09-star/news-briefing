## 1. 공통 설정
═══════════════════════════════════════

**Telegram (환경변수 — 값 하드코딩 금지)**

메시지는 **작업 폴더 `out/` 아래 파일에 진짜 줄바꿈으로 작성한 뒤 파일 경유로 발송**한다. 메시지 1개당 파일 1개(`out/msg1.txt`, `out/msg2.txt` …). 발송이 끝나면 워크플로가 `out/`의 파일을 로그에 출력하고 아티팩트로 보관하므로, **발송본을 이 경로에 남기는 것이 사후 검증의 유일한 경로다.** (세션 안에서 `cat`을 찍어봐야 Actions 로그에는 남지 않는다.)
```
mkdir -p out

# 1) 작성 — heredoc 안에서는 개행이 그대로 개행으로 들어간다
cat > out/msg1.txt <<'EOF'
📰 ...
━━━ 건설/부동산 ━━━
기사 제목
https://tinyurl.com/xxxxxxx

기사 제목
https://tinyurl.com/xxxxxxx
EOF

# 2) 발송 — text@파일 형식이면 curl이 파일 내용의 개행을 %0A로 정확히 인코딩
curl -s "https://api.telegram.org/bot${TELEGRAM_BOT_TOKEN}/sendMessage" \
  -d "chat_id=${TELEGRAM_CHAT_ID}" --data-urlencode "text@out/msg1.txt"
```

**줄바꿈 절대 규칙 (2026-07-27 사용자 지적)**: 셸 인자 안에 `\n`(백슬래시+n) 두 글자를 넣으면 curl이 그 두 글자를 그대로 인코딩해 **Telegram에 리터럴 `\n`이 텍스트로 표시된다**. 개행은 언제나 파일 안의 진짜 줄바꿈이어야 하고, 발송은 위의 `text@파일` 형식으로만 한다. `--data-urlencode "text=...\n..."` 직접 전달 금지.

plain text, 3000자 초과 시 분할, 한국어.

**발송 이력 기록 (필수 — 슬롯 간 중복 차단)**

발송을 마친 뒤 **이번에 내보낸 기사 전부**를 `out/sent.json`에 남긴다. 워크플로가 이걸 `state/sent.json`에 병합하고, **다음 슬롯의 collect.py가 읽어 같은 기사를 아예 수집하지 않는다.** 제목은 발송한 최종 제목, URL은 **TinyURL이 아니라 원본 URL**을 넣는다(단축 URL은 대조가 안 된다).
```
cat > out/sent.json <<'EOF'
[
 {"title": "발송한 기사 제목", "url": "https://원본-기사-URL"},
 {"title": "...", "url": "..."}
]
EOF
```
이 파일을 남기지 않으면 다음 슬롯에 같은 기사가 다시 나간다. **누락 시 완료 선언 금지.**


**시간 윈도우**: `pool.json`의 `windows_kst`가 확정값. **방식1은 당일 14:30~21:20**(직전 afternoon 슬롯의 끝에서 이어짐), **방식3은 당일 06:10~21:20**(morning 글로벌 윈도우가 끝난 지점에서 이어짐). 요일 특례 없음. 재계산 금지.

**절대 금지**
1. pool.json 밖 기사 임의 추가 금지 (폴백은 `--adhoc-naver`로만).
2. 창밖 기사·날짜/URL 확인 불가 기사 포함 금지.
3. 거짓말/수치 조작 금지. 모르면 "미확보". 폴백 카운트 거짓 기록 금지.
4. 검증되지 않은 내용 추가 금지. 방식3 요약은 기사 제목·RSS 메타 범위 내에서만 작성 (본문 미확인 시 제목 기반 1문장으로 제한).
5. 정치 뉴스 필터: 여야 정치·선거·여론조사·정책 찬반 논쟁 제외. 정부 부처 정책 발표·입법 의결 자체는 포함.
6. 대시보드·통계 페이지·위키피디아는 방식3에서 제외.

## 2. 실행 파이프라인
═══════════════════════════════════════
1. `pool.json` 읽기 (`Read` 도구).
2. `method1.건설` / `method1.금융`에서 §3·§4 우선순위·제외 규칙으로 각 10건 선별. `allowed_media: false` 제외. 중복 제거(§7-0) **및 `recently_sent` 대조로 슬롯 간 중복 제거(§7-1) — 생략 금지**.
3. 미달 시 폴백: `python scripts/collect.py --slot evening --adhoc-naver "<확장키워드>" --category <건설|금융>` — 키워드당 1회 상한, 도메인 가드(원 카테고리 유지), 포괄 키워드 "건설"·"부동산" 단독 금지.
4. **방식3 선별**: `method3.<테마>`에서 테마당 최대 2건. §4-1 우선순위 테마부터. 한국어 요약 1문장 작성(반드시 `- `로 시작). §7-0·§7-1 중복 제거는 방식3에도 동일 적용하며, **방식1과 방식3에 같은 사건이 걸치면 원 소스 국가 기준 한쪽에만** 넣는다.
5. 방식3 0건 테마 폴백: `python scripts/collect.py --slot evening --adhoc-rss "<확장쿼리>" --theme "#<테마>"` — 0라운드(§4-1 확장 쿼리 1회) → 1라운드(§4-2 대표 기업명, 상한 5기업) 순, 테마당 총 6쿼리 상한. 테마를 벗어난 기사 채택 금지.
6. 제목 복원 (필수): 네이버 API는 긴 제목을 "..."로 절단한다. 선별 확정 기사 중 `title_truncated: true`인 건은 `python scripts/full_title.py <URL...>`로 전체 제목 복원 — **`naver_link`가 있으면 그것을, 없으면 `url`을 전달** (여러 URL 동시 전달 가능). 복원 제목 끝의 " - 매체명"·" | 매체명"·" :: 매체명" 꼬리는 제거. 복원 실패(null) 시 잘린 제목 그대로 발송 + 푸터 "제목복원 실패 N건". 잘린 제목("...")을 복원 시도 없이 발송하는 것 금지.
7. TinyURL 축약 (선별 확정분만) → 게이트 검증(§0) → 발송(§8).

## 3. 건설/부동산 — 선별 우선순위
═══════════════════════════════════════
(수집 키워드는 `config/slots.json` — 기존 8그룹 동일)

**우선순위**: 부동산 정책 > 건설 법정관리 > 기한이익상실 > 부동산 신탁 > 그 외
※ 건설사 수주·광고형·분양 홍보 제외
※ **개별 물건 한 건짜리 기사 제외 (2026-07-24 지침 → 2026-07-30 강화)**

**판정 기준은 기사의 어조가 아니라 대상의 범위다.** 기사의 주어가 **특정 단지·특정 건물·특정 사업지 한 건**이면 사안의 종류를 불문하고 제외한다 — 분양·청약 성적, PF 점검, 매각·매물 등록, 인허가, 시공사 선정, 임차인 유치, 착공·준공 무엇이든 마찬가지다.

- **말머리·연재 형식은 판단 기준이 아니다.** `[부동산 PF 점검]`·`[사업지 돋보기]` 같은 분석형 말머리가 붙어 홍보처럼 보이지 않아도, 다루는 대상이 한 건이면 제외한다. 기존 규칙이 "홍보성"이라는 어조 기준이라 이 형식이 빠져나갔다.
- 실제 제외 사례 (2026-07-30 사용자 지적):
  - `[부동산 PF 점검] 효성중공업, 잠원동 복합개발` → 개별 사업지 1건
  - `중수청 품은 서울 을지로 '르네스퀘어' 다시 매물로` → 개별 건물 1건

**예외는 그 한 건이 시장 전반의 신호로 읽힐 때만.** 아래 중 하나에 해당해야 한다.
1. 대형 건설사·금융기관의 부실로 번지는 사안 (법정관리·EOD·대주단 손실 등)
2. 정책·제도 변경을 촉발했거나 촉발이 예상되는 사안
3. 업계 최초·최대 규모여서 시장 지표로 인용되는 거래

예외로 넣었으면 **푸터에 이유를 한 줄** 남긴다: `개별 물건 예외 포함: <제목 앞 20자> — <해당 사유 번호와 근거>`. 애매하면 제외한다.

## 7. 중복 제거
═══════════════════════════════════════

### 7-0. 이번 메시지 안에서
(a) URL 동일 (b) 제목 실질 동일 (c) 같은 사건 → 주 테마 1곳에만. [단독] 우선, 그 외 원보도 매체 우선.
**건설 섹션과 금융 섹션에 걸치는 기사도 한쪽에만 넣는다** (정책·규제 기사에서 자주 발생).

### 7-1. 슬롯 간 중복 — `recently_sent` 대조 (필수)

`pool.json`의 **`recently_sent`** 는 직전 슬롯들이 최근 48시간 안에 이미 발송한 기사 제목 목록이다. 제목·URL이 거의 같은 건은 collect.py가 이미 수집 단계에서 걸러냈으므로, **여기서 걸러야 할 것은 "같은 사건을 다룬 다른 기사"** 다. 제목도 매체도 URL도 다르지만 독자가 보기에 같은 뉴스인 경우다.

**같은 사건 판정**: `(주체 기관·기업) + (조치·행위) + (대상)` 세 축이 사실상 같으면 같은 사건이다. 매체·표현·각도가 달라도 제외한다.
- 예: `금감원 특사경, 엘앤에프 인지수사` ↔ `엘앤에프 수사 착수한 금감원 특사경, 테슬라 계약 정조준` → **같은 사건, 제외**
- 예: `금감원, 가계대출 규제 강화` ↔ `한국은행 기준금리 동결` → 다른 사건, 포함

**예외 — 실질적 진전이 있으면 포함한다.** 새 결정·새 수치·새 당사자·국면 전환이 있는 후속 보도는 새 뉴스다. 이 경우 요약이 없는 방식1에서는 제목 자체가 진전을 담고 있어야 하며, 무엇이 새로운지 푸터에 한 줄로 밝힌다: `후속 포함: <기사 제목 앞 20자> — <새로운 점>`.
- 단순 재보도·해설·반응 기사("~에 업계 술렁", "~ 무엇을 의미하나")는 진전이 아니다. 제외한다.

**판단이 애매하면 제외하는 쪽으로 기운다.** 중복 발송이 누락보다 체감 손해가 크다는 것이 사용자 지침이다(2026-07-27).

**푸터에 제외 건수를 기록한다**: `슬롯간 중복 제외 <N>건 (recently_sent <M>건 대조)`. 0건이면 0건이라고 적는다.

## 8. 메시지 형식 (v7: 제목 + 단축URL, 번호·화살표 없음)
═══════════════════════════════════════
- 모든 URL은 TinyURL 축약: `https://tinyurl.com/api-create.php?url=<원본URL>` GET → 응답 본문이 단축 URL. 실패 시 해당 건만 원본 fallback + 푸터 "단축 실패 N건".
- 번호(1.)·화살표(→) 사용 금지. 제목 한 줄, 다음 줄에 단축 URL. **기사 사이에는 빈 줄 1개** (2026-07-27 사용자 지침 — 가독성). 섹션 헤더는 유지.

### 8-1. 방식1 (제목 + 단축URL, 요약 없음)
```
📰 오후 9시 30분 뉴스 브리핑 (YYYY.MM.DD)

━━━ 건설/부동산 ━━━
기사 제목
https://tinyurl.com/xxxxxxx

기사 제목
https://tinyurl.com/xxxxxxx

...

━━━ 경제/금융 ━━━
기사 제목
https://tinyurl.com/xxxxxxx

...
```

### 8-2. 방식3 (3단: 제목 / 요약 / 단축URL)
```
🌐 오후 9시 30분 글로벌 브리핑 (YYYY.MM.DD)

━━━ #AI ━━━
기사 제목
- 요약 1문장 (한국어)
https://tinyurl.com/xxxxxxx

기사 제목
- 요약 1문장 (한국어)
https://tinyurl.com/xxxxxxx

...
```
방식3 요약은 반드시 `- `로 시작한다.

**메시지 분할**: MSG A: 방식1 전체(건설+금융) / B: #AI·#AI_Infra·#AI_Labs·#반도체 / C: #석유·#LNG·#소재_에너지·#산업재 / D: #소비재·#원자력_전력·#우주 / E: #전쟁_지정학·#스테이블코인 + 푸터. 각 3000자 이내이고, 방식1이 3000자를 넘으면 건설/금융으로 한 번 더 나눈다. 0건 테마만 있는 메시지는 보내지 않고 해당 테마를 푸터의 0건 목록으로 넘긴다.

### 8-3. 발송 검증 푸터 (마지막 메시지에만)
```
━━━ 발송 검증 ━━━
URL <실제>/<목표>, 방식1 건설 <N> + 금융 <M>, 방식3 테마 <T>/13
수집기 naver <K>쿼리 + rss <R>쿼리, 창밖 기계제외 <X>건, 디코딩 실패 <D>건, 폴백 <F>회, 단축 실패 <S>건
슬롯간 중복 제외 <N>건 (recently_sent <M>건 대조)
(G0-6) 미달 섹션·0건 테마별 시도 카운트
```
**G0-1 재확인**: 단축 후에도 전체 메시지의 `https?://` 개수 = 발송 기사 개수 (방식1 20 + 방식3 실제 건수).
