## 1. 공통 설정
═══════════════════════════════════════

**Telegram (발송은 워크플로가 한다 — 이 세션은 파일만 쓴다)**

메시지는 **작업 폴더 `out/` 아래 파일에 진짜 줄바꿈으로 작성하기만 한다.** 메시지 1개당 파일 1개, 보낼 순서대로 번호(`out/msg1.txt`, `out/msg2.txt` …).

**Telegram API를 이 세션에서 직접 호출하는 것은 금지한다.** 발송은 워크플로의 `Telegram 발송` 스텝이 `out/msg*.txt`를 번호순으로 보내고, 매 응답의 `ok` 필드를 검사해 거부되면 잡을 실패시킨다. 세션 안에서 `curl`을 쏘면 그 응답이 Actions 로그에 남지 않으므로, Telegram이 메시지를 거부해도 잡은 초록색으로 끝나고 아무도 모른다 — 2026-08-14에 실제로 그렇게 됐다(잡 전부 success, 사용자에게는 아무것도 도착하지 않음).

따라서 **`out/msg*.txt`를 남기는 것이 곧 발송이다.** 파일을 안 남기면 아무것도 나가지 않는다. 이 파일들은 로그 출력·아티팩트 보관도 겸하므로 사후 검증 경로이기도 하다.

**백그라운드 위임 금지 (2026-08-24 사고).** 선별·제목복원·축약·파일 작성을 백그라운드 태스크나 서브에이전트에 넘기고 먼저 응답을 끝내지 말 것. 헤드리스 세션은 최종 응답을 내보내는 순간 종료되고, 그때까지 안 끝난 백그라운드 작업은 상한(기본 600초)에서 잘려 죽는다. 실제로 midmorning 이 그렇게 통째로 누락됐다 — 세션은 "백그라운드 에이전트에 위임했습니다"라고 답하고 끝났고 `out/` 은 비어 있었다. **`out/msg*.txt` 와 `out/sent.json` 을 이 세션에서 직접 다 쓴 뒤에 응답을 끝낸다.**
```
mkdir -p out

# 1) 작성 — heredoc 안에서는 개행이 그대로 개행으로 들어간다
cat > out/msg1.txt <<'EOF'
📰 ...
━━━ 건설/부동산 ━━━
기사 제목
https://tinyurl.com/xxxxxxx

기사 제목
https://tinyurl.com/xxxxxxx
EOF

# 2) 발송 — 하지 않는다. 워크플로가 out/msg*.txt 를 번호순으로 보낸다.
```

**줄바꿈 절대 규칙 (2026-07-27 사용자 지적)**: 파일 안에 `\n`(백슬래시+n) 두 글자를 적으면 **Telegram에 리터럴 `\n`이 그대로 보인다**. 워크플로는 `--data-urlencode "text@파일"`로 보내므로 파일 안의 **진짜 줄바꿈만** 개행이 된다. heredoc 안에서 `\n` 이스케이프를 쓰지 말 것.

plain text, 3000자 초과 시 분할, 한국어.

**발송 이력 기록 (필수 — 슬롯 간 중복 차단)**

발송을 마친 뒤 **이번에 내보낸 기사 전부**를 `out/sent.json`에 남긴다. 워크플로가 이걸 `state/sent.json`에 병합하고, **다음 슬롯의 collect.py가 읽어 같은 기사를 아예 수집하지 않는다.** 제목은 발송한 최종 제목, URL은 **원본 URL**을 넣는다 — 단축 URL은 다음 슬롯에서 대조가 안 된다. (워크플로의 단축 스텝은 `out/msg*.txt` 만 건드리고 `out/sent.json` 은 그대로 둔다.)
```
cat > out/sent.json <<'EOF'
[
 {"title": "발송한 기사 제목", "url": "https://원본-기사-URL"},
 {"title": "...", "url": "..."}
]
EOF
```
이 파일을 남기지 않으면 다음 슬롯에 같은 기사가 다시 나간다. **누락 시 완료 선언 금지.**


**시간 윈도우**: `pool.json`의 `windows_kst`가 확정값 (당일 09:50~14:30 — 직전 midmorning 슬롯의 끝에서 이어짐, 요일 특례 없음). 재계산 금지.

**절대 금지**
1. pool.json 밖 기사 임의 추가 금지 (폴백은 `--adhoc-naver`로만).
2. 창밖 기사·날짜/URL 확인 불가 기사 포함 금지.
3. 거짓말/수치 조작 금지. 모르면 "미확보". 폴백 카운트 거짓 기록 금지.
4. 검증되지 않은 내용 추가 금지.
5. 정치 뉴스 필터: 여야 정치·선거·여론조사·정책 찬반 논쟁 제외. 정부 부처 정책 발표·입법 의결 자체는 포함.
6. **칼럼·사설 제외 (2026-11-01 사용자 지침 "칼럼 가져오지마")**: 필자의 주장·논평이 본문인 글은 발송하지 않는다 — 사설·칼럼·기고·시론·논설·기자수첩·취재수첩·독자투고, `[○○칼럼]`·`[데스크에서]`·`[○○의 눈]` 류 말머리가 붙은 글, `Opinion:`·`Column:` 접두어가 붙은 글, URL 경로에 `/opinion`·`/column`·`/editorial` 이 들어간 글. **판정은 말머리가 아니라 내용이다** — 새 사실(일정·금액·당사자·결정)을 전하면 기사, 이미 알려진 사실에 해석·주장·제언을 덧붙인 것이면 칼럼이다. 애매하면 제외한다. `collect.py` 가 말머리·URL 경로로 1차 제외하고 그 수를 `collector_stats.rejected_opinion` 에 남기지만, 매체 고유 말머리나 말머리 없는 논설은 그 필터를 빠져나오므로 **선별에서 직접 판단해야 한다**. 이건 순위를 내리는 규칙이 아니라 **제외**다 — 후보가 모자라면 칼럼으로 채우지 말고 §G0-3 대로 "※ N건만 확인됨"으로 보고한다.

4. 제목 복원 (필수): 네이버 API는 긴 제목을 "..."로 절단한다. 선별 확정 기사 중 `title_truncated: true`인 건은 `python scripts/full_title.py <URL...>`로 전체 제목 복원 — **`naver_link`가 있으면 그것을, 없으면 `url`을 전달** (여러 URL 동시 전달 가능). 복원 제목 끝의 " - 매체명"·" | 매체명"·" :: 매체명" 꼬리는 제거. 복원 실패(null) 시 잘린 제목 그대로 발송 + 푸터 "제목복원 실패 N건". 잘린 제목("...")을 복원 시도 없이 발송하는 것 금지.
5. 게이트 검증(§0) → 발송본 작성(§8). URL 단축은 워크플로가 발송 직전에 한다.

## 2-1. 제목 판정 — 선별 전에 모든 후보에 먼저 적용 (2026-11-03 사용자 지침)
═══════════════════════════════════════
사용자: "키워드도 키워드인데 제목을 분석해서 줘. 지금은 너무 쓸데없는 게 많이 와."

`pool.json` 후보마다 **제목을 읽고 두 가지를 묻는다.**
 ① 새 사실이 있는가 — 결정·조치·수치(잔액·규모·비율)·일정·당사자 중 하나라도 제목에 드러나는가.
 ② 업권 분석에 쓰이는가 — 은행·보험·증권·부동산 업계의 영업·건전성·규제·구조를 보는 사람에게 필요한 사실인가.
둘 다 "예"인 기사만 §3·§4 선별로 넘긴다.

**아래 유형은 제외한다.** 2026-11-02~03 실제 발송분에서 뽑은 사례다.
 A. **시황·주가 등락** — 지수·종목 등락, 낙폭·상승폭 순위, `[fn오후시황]` 류. 예: "코스피 10월 16% 급락…월간 낙폭 역대 7위", "'-29% 인텔 쇼크'에 긴장한 코스피"
 B. **소비자·생활 정보** — 가입 요령, 절세 팁, Q&A형("~는?"), 금리 올라 '한숨' 류 체감 기사, 소비자 유의 안내. 예: "전세 준 내 집, 2년 늦게 팔면 세금 1.7억 더 낸다", "종부세 아끼려다 취득세까지…", "청년, 부모차 무사고운전·군경력 인정…車보험 가입체계 개편", "신용대출 금리도 7% 코앞…'빚투족' 한숨"
 C. **제언·주장·인터뷰** — 제목이 누군가의 주장·당부("~해야", "~풀어야")이고 새 사실이 없는 것, 대담·인터뷰. 예: ""DC형 퇴직연금, 위험자산 70%룰 풀어야"", ""대부업 합법 금융인데 부정 낙인…"", "오균 서울연구원장 "서울의 핵심은 한강""
 D. **지자체·자치구 행정** — 시·군·구의 기준 마련·조직 개편·건의·협약. 예: "인천시, 노후도시 재건축 '주민 대표권' 기준 마련", "양주시, LH에 택지개발 현안 16건 건의", "바빠진 자치구…관련 조직 개편". (서울시·광역 단위 정책이 시장 전반에 닿으면 예외. 금융사가 당사자인 금고 선정은 은행 기사로 본다.)
 E. **지역 단위 재가공** — 한 시·도의 경기·통계를 떼어 낸 기사. 예: "스마트폰 판매 호조에 대구경북 경기 개선", "경북 집합상가 공실률 전국 1위". (전국·서울 헤드라인 통계 기사가 따로 있으면 그것을 넣는다.)
 F. **개인 범죄·사건** — 검거·사기·횡령 사건 보도. 예: "다가구주택 '유령 호실' 악용해 27억 꿀꺽…11명 검거". (금융사 내부통제 사고·대규모 정보유출은 업권 기사다 — 포함.)
 G. **새 사실 없는 기획·트렌드** — 현상 묘사·전망만 있는 연재·피처. 예: "[전문가 10인 진단] 서울 집값 더 오른다", "같은 신용대출, 다른 이유…[한강로 경제브리핑]". 말머리가 아니라 ①로 판단한다 — 기획 기사라도 새 수치·결정이 제목에 있으면 통과.
 H. **화제성·인물 동정** — 연봉·성과급 화제, 행사·세미나·MOU 단순 소식. 예: "'연봉 7억' 은행연합회장 누가 될까", "[단독] '1억 성과급'도 못 막았다…국민연금 '줄퇴사'"
 I. **해외 가상자산 사건의 후속 추적** — 해킹 자금 세탁 경로, 해외 거래소 출금 재개 등. 예: "북한 해커, 탈취한 코인 2차 세탁 착수", "8.4조 털린 바이낸스, 단계적 출금 재개". (국내 당국의 대응 조치는 규제 기사로 1건만.)
 J. **개별 단지 분양·청약** — 기존 개별 물건 제외 규칙과 같다. 예: "'로또 줍줍'…과천 무순위 오늘 접수", "11월 전국 분양…'반포 한 단지'"

**이 판정은 "건수를 줄이지 않는다" 원칙보다 앞선다.** 쓸데없는 기사로 10건을 채우지 않는다. 통과 후보가 모자라면 먼저 폴백(키워드 확장)을 쓰고, 그래도 모자라면 §G0-3 대로 "※ N건만 확인됨"으로 보낸다. 2026-09-29 기준("순위만 내리고 제외는 안 함")과 논조 균형의 "건수 축소 금지"는 **이 판정을 통과한 기사 안에서** 적용한다.

**애매하면 ①을 다시 본다.** 제목에 새 사실이 있으면 통과, 없으면 제외.

**푸터에 한 줄**: `제목 판정 제외 <N>건 (A <a> · B <b> · …)` — 0건인 유형은 생략.

## 3. 건설/부동산 — 선별 우선순위

## 7. 중복 제거
═══════════════════════════════════════

### 7-0. 이번 메시지 안에서
(a) URL 동일 (b) 제목 실질 동일 (c) 같은 사건 → 주 테마 1곳에만. [단독] 우선, 그 외 원보도 매체 우선.
**건설 섹션과 금융 섹션에 걸치는 기사도 한쪽에만 넣는다** (정책·규제 기사에서 자주 발생).

### 7-1. 슬롯 간 중복 — `recently_sent` 대조 (필수)

`pool.json`의 **`recently_sent`** 는 직전 슬롯들이 최근 48시간 안에 이미 발송한 기사 제목 목록이다. 제목·URL이 거의 같은 건은 collect.py가 이미 수집 단계에서 걸러냈으므로, **여기서 걸러야 할 것은 "같은 사건을 다룬 다른 기사"** 다. 제목도 매체도 URL도 다르지만 독자가 보기에 같은 뉴스인 경우다.

**같은 사건 판정**: `(주체 기관·기업) + (조치·행위) + (대상)` 세 축이 사실상 같으면 같은 사건이다. 매체·표현·각도가 달라도 제외한다.
- 예: `금감원 특사경, 엘앤에프 인지수사` ↔ `엘앤에프 수사 착수한 금감원 특사경, 테슬라 계약 정조준` → **같은 사건, 제외**
- 예: `금감원, 가계대출 규제 강화` ↔ `한국은행 기준금리 동결` → 다른 사건, 포함

**예외 — 실질적 진전이 있으면 포함한다.** 새 결정·새 수치·새 당사자·국면 전환이 있는 후속 보도는 새 뉴스다. 이 경우 요약이 없는 방식1에서는 제목 자체가 진전을 담고 있어야 하며, 무엇이 새로운지 푸터에 한 줄로 밝힌다: `후속 포함: <기사 제목 앞 20자> — <새로운 점>`.
- 단순 재보도·해설·반응 기사("~에 업계 술렁", "~ 무엇을 의미하나")는 진전이 아니다. 제외한다.

**판단이 애매하면 제외하는 쪽으로 기운다.** 중복 발송이 누락보다 체감 손해가 크다는 것이 사용자 지침이다(2026-07-27).

**푸터에 제외 건수를 기록한다**: `슬롯간 중복 제외 <N>건 (recently_sent <M>건 대조)`. 0건이면 0건이라고 적는다.

## 8. 메시지 형식 (v7: 제목 + URL, 번호·화살표 없음)
═══════════════════════════════════════
- **URL 단축은 이 세션이 하지 않는다.** 발송본에는 **원본 URL 을 그대로** 한 줄로 적는다. 단축은 발송 직전에 워크플로의 `scripts/shorten.py` 가 한다(is.gd → v.gd → TinyURL 순서로 시도하고, 돌아온 값의 형태·유일성·왕복을 검증한다). 세션 안에서 단축기를 부르면 그 응답이 Actions 로그에 남지 않아 무엇이 왜 실패했는지 볼 수가 없다 — 2026-09-07 evening 이 그랬다: TinyURL 이 45건 **전부에 같은 무관 URL** 을 200으로 돌려줬고, 세션이 알아채 원본으로 되돌린 덕에 잘못된 링크가 나가지는 않았지만 브리핑 전체가 긴 URL 로 나갔다.
- 번호(1.)·화살표(→) 사용 금지. 제목 한 줄, 다음 줄에 URL. **기사 사이에는 빈 줄 1개** (2026-07-27 사용자 지침 — 가독성). 섹션 헤더는 유지.

기사 제목
https://tinyurl.com/xxxxxxx

기사 제목
https://tinyurl.com/xxxxxxx

...

━━━ 경제/금융 ━━━
기사 제목

━━━ 발송 검증 ━━━
